# Harness 5.3.12

Release date: 2026-11-26.

Harness 5.3.12 adds Hermes web adaptation and font preferences, and fixes profile isolation, stop-command races, repeated Settings saves, tray exit, and portable-update recovery.

## Agent support and appearance

- Dedicated Agent support now targets **Hermes Agent and OpenClaw**. Other products, including existing DeepSeek profiles, use Generic web hosting while retaining environment identity, URL, and browser data.
- Hermes support reads model and running state from the official **`hermes webapp`** interface and uses its current chat composer's stop control. It does not implement native Hermes Gateway management. The [Gateway management design](https://github.com/guijianchou/Harness/blob/5.3.12/docs/gateway-management.md) documents the intended scope and upstream contracts; OpenClaw retains its existing opt-in native Gateway features.
- Settings > Appearance offers System UI or bundled Noto Sans SC and a 10–32 px base font size. Saved preferences apply to native controls and hosted content without a remote font service. Icons and code fonts retain their families, and web zoom remains independent.

## Reliability and isolation fixes

- Validate WebView2's effective user-data folder before creating a controller. Environment-variable or policy overrides that redirect it to another profile produce an explicit error instead of silently sharing browser data.
- Make heartbeat, latency, and diagnostic HTTP probes stateless: no shared cookie jar or automatic redirects. Align single-instance pipe names with the Windows session scope and back off listener failures to prevent repeated error loops.
- Bind Stop and asynchronous fallbacks to the original page, session, run, and deadline. Expired commands cannot target a later run, and Generic pages receive no Agent stop command.
- Resolve the selected environment by stable ID when environments are renamed. Clear committed edit flags after a successful Settings save so a later save cannot overwrite newer live changes.
- Keep the window accessible if the tray is unavailable. Close again within 15 seconds to exit if tray recovery still fails; successful recovery clears the pending confirmation. Exit waits for an active Settings save to finish.
- Create diagnostic ZIPs with unique names and exclusive creation so repeated or concurrent exports cannot overwrite previous archives.
- Continue rollback and restart of the previous version even when update-result files cannot be written. If exclusive update ownership cannot be reacquired, preserve the directories for recovery; fallback restart only launches the restored previous version.
- Normalize only generated apphosts and three EXEs in the update staging directory to Medium integrity. Parent directories, existing installations, user-data permissions, and DACLs are unchanged; no elevation is requested. Include the x86 test host in build normalization. Failed staging normalization leaves the current application running.

## Validation boundary

Automated checks cover backend migration, hosted UI commands, profile and HTTP isolation, Settings changes, tray behavior, diagnostic exports, typography, and portable update recovery. **Real Hermes/OpenClaw VPS authentication, reverse proxies, streaming, and server-side cancellation have not been validated in this release work.** Hermes webpage adaptation and Gateway research do not imply complete remote service, configuration, or log management.

## Installation

Official portable builds from 5.3.9 onward can use **Settings > About > Save settings and restart to update**. For manual installation, download `Harness-5.3.12-win-x64.zip`, extract the entire archive into a new normal user directory, close the old Harness instance, and run `Harness.exe`.

Targets Windows 11 24H2 (build 26100) or later. .NET and Windows App SDK are included; Microsoft Edge WebView2 Runtime is required. Settings and browser profiles remain in `%LOCALAPPDATA%\Harness`. See [portable update and recovery details](https://github.com/guijianchou/Harness/blob/5.3.12/docs/portable-updates.md).

## 简体中文

发布日期：2026-11-26。

- Agent 专用支持仅面向 **Hermes Agent 与 OpenClaw**。其他产品（含旧 DeepSeek 配置）使用普通 Web 承载，保留环境身份、URL 和浏览器资料。
- Hermes 适配官方 **`hermes webapp`** 的模型、运行状态与当前聊天输入区停止控件；**尚未实现原生 Hermes Gateway 管理**。[Gateway 管理设计](https://github.com/guijianchou/Harness/blob/5.3.12/docs/gateway-management.md) 记录目标范围与官方契约，OpenClaw 保留现有按需启用的原生 Gateway 功能。
- “设置 > 外观”提供 System UI、随包提供的 Noto Sans SC 和 10–32 px 基础字号，保存后作用于原生控件与内嵌页面，无需远程字体服务；图标、代码字体与网页缩放独立保留。
- 创建 WebView2 控制器前检查实际资料目录，拒绝环境变量或策略将其导向其他资料；HTTP 心跳、延迟与诊断探测不共享 Cookie、不自动跟随重定向；单实例激活管道与 Windows 会话作用域对齐，并对监听失败退避。
- 停止操作及异步回退绑定原页面、会话、运行和截止时间，过期命令不会影响新运行，普通网页不接收 Agent 停止命令。
- 环境重命名按稳定 ID 保留当前选择；成功保存后清除编辑标记，避免后续保存覆盖其他位置已提交的实时设置。
- 托盘不可用时保留窗口，15 秒内再次关闭且恢复仍失败时退出；恢复成功清除确认，退出前仍等待正在执行的设置保存。
- 诊断 ZIP 使用唯一名称和独占新建，重复或并发导出不覆盖旧文件。
- 更新结果写入失败不阻断旧版回滚重启；无法重新获取独占更新租约时保留目录供恢复，兜底仅启动已恢复的旧版。
- 仅将生成的 apphost 与更新暂存区的三个 EXE 规范化为 Medium 完整性，并覆盖 x86 测试宿主；不修改父目录、既有安装、用户资料权限或 DACL，不请求提权。暂存标签准备失败时保留当前应用运行。

自动检查覆盖后端迁移、网页命令、资料与 HTTP 隔离、设置、托盘、诊断、字体和便携更新恢复。**本次未完成真实 Hermes/OpenClaw VPS 的认证、反向代理、流式输出与服务端取消验收**，网页辅助适配和研究文档不代表已交付完整的远程服务、配置或日志管理。

5.3.9 及之后的官方便携包可在“设置 > 关于”选择“保存设置并重启更新”。手动安装请将 `Harness-5.3.12-win-x64.zip` 完整解压到新的普通用户目录，退出旧版，再运行 `Harness.exe`。面向 Windows 11 24H2（26100）及以上，内含 .NET 和 Windows App SDK，仍需系统 WebView2 Runtime；配置与浏览器资料继续保存在 `%LOCALAPPDATA%\Harness`。
